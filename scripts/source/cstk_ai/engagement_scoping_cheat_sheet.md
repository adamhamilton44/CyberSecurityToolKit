# Engagement Scoping & Rules of Engagement (RoE) Questionnaire

This cheat sheet contains the mandatory questions that an automated tool or scoping script must ask **before** executing any security scanning, penetration testing, or ethical hacking tools.

---

## 1. Scope Boundaries & Target Asset Identification
*What infrastructure is legally authorized for testing?*

* **TARGET_LIST**: What are the specific IP addresses, CIDR blocks, domain names, or application URLs authorized for this engagement?
* **OUT_OF_SCOPE**: Are there any explicitly forbidden hostnames, IPs, subnets, or API endpoints that must be excluded from all tools?
* **THIRD_PARTY_INFRASTRUCTURE**: Do any of the targets reside on third-party infrastructure (e.g., AWS, Azure, GCP, or a hosted SaaS provider)?
  * *Follow-up:* Has the owner obtained explicit written authorization from the provider?
* **ENVIRONMENT_TYPE**: Are these production, staging, development, or UAT (User Acceptance Testing) environments?
* **HOSTING_LOCATION**: Are the targets externally accessible over the public internet, or do they require internal network access (e.g., VPN, local network drop, or internal agent)?

---

## 2. Technical Constraints & Tool Behavior
*How must the automated tools behave to ensure safety and compliance?*

* **MAX_THROUGHPUT**: What is the maximum allowed requests-per-second (RPS) or bandwidth limit for automated scanners to prevent service degradation?
* **SCAN_INTENSITY**: Are aggressive, intrusive, or destructive checks allowed, or must tools restrict activity to passive and low-impact exploration?
* **CREDENTIALED_TESTING**: Will automated tools be provided authentication credentials (e.g., API keys, service tokens, SSH keys, or application test accounts)?
  * *Follow-up:* If yes, what are the specific accounts and active user roles?
* **EXPLOITATION_ALLOWED**: Is automatic vulnerability exploitation permitted (e.g., running automated Metasploit modules), or should the tool stop immediately upon finding a potential vulnerability flag?
* **DENIAL_OF_SERVICE**: Are Denial of Service (DoS/DDoS) tests, stress testing, or buffer overflow checks explicitly permitted or strictly forbidden?

---

## 3. Operational Timeline & Scheduling
*When is the tool legally allowed to operate?*

* **START_TIME**: What is the exact calendar date and timestamp when tool execution is legally allowed to begin?
* **END_TIME**: What is the exact date and timestamp when all automated tool traffic must absolutely cease?
* **TESTING_WINDOWS**: Are tools restricted to specific daily time frames (e.g., off-peak hours only, such as 22:00 to 04:00 local time), or can they run 24/7?
* **TIME_ZONE**: What specific time zone governs the start, end, and daily operational windows?

---

## 4. Operational Sign-offs & Identifiers
*How does the client know the traffic is coming from the authorized team?*

* **SOURCE_IPS**: What are the explicit source IP addresses or VPN egress points that the automated tools will use? (Provide these to the client so they can whitelist or monitor them).
* **CUSTOM_HEADERS**: Should the tool append a distinct identifier string (e.g., a custom `User-Agent` header or an HTTP header like `X-Engagement-Id: <ID>`) so web applications can trace authorized activity?
* **IDS_IPS_BYPASS**: Should the client whitelist the tool's source IPs on firewalls, WAFs, or Intrusion Detection Systems (Overt/Gray-Box testing), or should the tool attempt to bypass active security defenses (Covert testing)?

---

## 5. Points of Contact & Escalation Procedures
*Who to reach instantly if things break down.*

* **PRIMARY_POC**: Who is the primary technical Point of Contact representing the client? (Name, Title, Phone Number, Secure Signal/Email).
* **EMERGENCY_POC**: Who is the 24/7 emergency operational contact authorized to order an immediate cease-fire if a system crashes? (Name, Direct Mobile Line).
* **INCIDENT_RESPONSE_NOTIFICATION**: Will the client's internal Security Operations Center (SOC) or Blue Team be notified about this test?
* **BREACH_ESCALATION**: If the tool accidentally uncovers an active, real-world compromise or an unauthorized backdoor during the assessment, who must be alerted immediately?

---

## 6. Data Handling & Security
*How captured artifacts and logs must be stored.*

* **SENSITIVE_DATA_POLICY**: If the tool encounters Personally Identifiable Information (PII), payment card data (PCI), or health data (PHI), should it mask/truncate the data, stop scanning, or log it securely?
* **OUTPUT_ENCRYPTION**: What encryption requirements apply to the logs, raw outputs, and vulnerability metrics generated by this script?
